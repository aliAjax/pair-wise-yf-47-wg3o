# pair-wise-yf-47 城市轨道交通突发停运应急协同

源提示词摘要：调度员、车站值班员、公交接驳负责人和客服主管协同处理突发停运，维护事故时间线、区段与车站状态、接驳计划、跨岗位确认和对外口径；弱网时需要使用缓存并把操作放入本地队列。

## 核心协同规则

### 车站状态 ↔ 接驳计划联动
- 接驳计划必须集齐**调度员 + 公交接驳负责人**双重确认才生效；单一确认只能停留在「待确认」。
- 双确认成立时锁定确认依据（车辆数 + 覆盖车站的状态快照 `basis`）。
- 计划覆盖的车站状态变化，或计划车辆数调整时，相关确认**立刻作废**：清空审批、回到「待确认」、记录作废原因，旧确认不能再执行。
- 执行前按双重确认和确认依据重新校验；依据已变（如车站重新封闭）则驳回执行并作废确认。

### 角色权限
- 车站状态：仅调度员、车站值班员可修改。
- 接驳计划（新建/提交/确认/调车/执行）：仅调度员、公交接驳负责人可操作。
- **客服主管只读**：不能改动车站状态，也不能确认或修改计划。
- 两岗位同时改同一车站：弱网重连提交时按角色优先级放行（调度员 > 车站值班员），低优先级方的并发修改被拦截并要求核对现场。

### 弱网队列
- 弱网期间操作本地乐观生效，同时按**依赖关系**排队（如同岗位连续改同一车站、计划的提交→确认→执行、执行依赖覆盖车站的状态变更先落库）。
- 重新连接后先**合并**待同步操作：同岗位连续修改合并为最后一次、重复提交/确认去重、连续调车合并为最后一次；依赖边随之重写。
- 合并后按拓扑顺序逐条提交，**某条失败不阻塞后续操作**；失败条目保留原因与重试次数，可重试或放弃。
- 执行类操作在提交侧二次复核双确认与确认依据，依据失效时回滚本地乐观状态并作废确认。

## 技术栈

Next.js15、TypeScript、App Router、Ant Design、Zustand、TanStack Query、React Hook Form、Zod、next-intl、date-fns、MapLibre。
